# what is babel
- - Babel is a JavaScript compiler that allows developers to write modern JavaScript code and convert it into a version that is compatible with older browsers. It enables the use of new JavaScript features
- - Babel is often used in conjunction with React to transform JSX syntax into regular JavaScript code that browsers can understand. It also allows developers to use the latest ECMAScript features without worrying about browser support.

# vite.config.js
- - Vite is a build tool that aims to provide a faster and leaner development experience

# package.json
- - The package.json file is a crucial component of a React application. It serves as a manifest for the project, containing metadata about the application, its dependencies, scripts, and other configuration details. It allows developers to manage and install packages, define scripts for building and running the application, and specify project information such as name, version, and author.

# package-lock.json
- - The package-lock.json file is automatically generated when you install dependencies using npm. It records the exact versions of the installed packages and their dependencies, ensuring that the same versions are used when the project is installed on different machines or by different developers. This helps maintain consistency and prevents potential issues caused by version discrepancies.


# node_modules
- - The node_modules folder is where all the installed dependencies of a React application are stored.
- - It contains the actual code for the packages listed in the package.json file, allowing the application to access and use those dependencies during development and runtime. The node_modules folder is typically not included in version control systems like Git, as it can be regenerated by running npm install based on the package.json file.

# what is components
- - Components are the building blocks of a React application. They are reusable and self-contained pieces of code that define how a part of the user interface (UI) should look and behave. Components can be thought of as JavaScript functions or classes that return JSX (JavaScript XML) to describe the UI structure. They can accept input in the form of props (properties) and manage their own state, allowing for dynamic and interactive user interfaces. By breaking down the UI into smaller components, developers can create modular and maintainable code, making it easier to manage and update the application over time.

## Rules of components
- - Components must start with a capital letter.
- - Components can be either functional or class-based, but functional components are more commonly used in modern React development.
- - Components should be reusable and focused on a single responsibility or feature.
- - Components can be nested within other components to create a hierarchical structure.
- - Components can accept props (properties) to customize their behavior and appearance.
- - Components can manage their own state using the useState hook (for functional components) or the state property (for class-based components).
- - Components should be designed to be composable, allowing them to be combined and reused in different parts of the application.
- - Components should follow the principles of separation of concerns, keeping the UI logic separate from the business logic.
- - Components should be tested to ensure they function correctly and handle different scenarios.
- - Components should be documented to provide clear instructions on how to use them and what props they accept.

- - components call as a element  <App />

## what is props
- - Props (short for properties) are a mechanism in React that allows data to be passed from a parent component to a child component. They enable components to be reusable and customizable by allowing them to receive input values from their parent components. Props are read-only, meaning that a child component cannot modify the props it receives; instead, it can use them to render dynamic content or trigger specific behavior. By using props, developers can create flexible and modular components that can be easily reused in different parts of an application, promoting a more maintainable and scalable codebase.

### ways to pass props
- - Props can be passed to a child component by including them as attributes when rendering the component

```jsx
  <ChildComponent propName={propValue} />
  ```
- - Props can also be passed as an object using the spread operator
```jsx
  const props = { propName1: value1, propName2: value2 };
  <ChildComponent {...props} />
  ```   
- - Props can be passed as children by wrapping the child component with the parent component and placing the content between the opening and closing tags of the parent component
```jsx
  <ParentComponent>
    <ChildComponent />
  </ParentComponent>
  ```

- - children props can be accessed in the child component using the special `children` prop, which contains the content passed between the opening and closing tags of the parent component. The child component can then render or manipulate this content as needed.

```jsx
  const ChildComponent = (props) => {
    return (
      <div>
        {props.children}
      </div>
    );
  };
```
